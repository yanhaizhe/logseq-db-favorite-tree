# 技术方案

本文档描述 `Logseq DB Favorite Tree` 的目标、模块边界、关键数据流、状态模型、交互实现与后续演进方向，作为后续维护和迭代的基础设计说明。

## 1. 设计目标

### 1.1 核心目标

- 以 Logseq 收藏页作为树的根节点来源
- 以页面属性关系构建稳定的层级导航结构
- 提供比原生收藏夹更清晰的树形浏览能力
- 以悬浮面板 / 悬浮球方式常驻，不强依赖侧边栏
- 在不同 graph 下分别记忆使用状态，避免互相污染

### 1.2 非目标

- 不支持 file graph
- 不直接修改页面层级关系，只做读取和展示
- 不通过拖拽改写父子关系，拖拽仅用于同级排序
- 不承担通用文件树或数据库浏览器角色

## 2. 功能范围

- 收藏根节点加载
- 属性驱动层级关系解析
- 懒加载展开与循环检测
- 当前页高亮与多路径定位
- 聚焦当前路径 / 折叠其他分支
- 树内搜索、祖先路径保留、多命中切换导航
- 默认标题排序与同级拖拽自定义排序
- 排序模式切换（默认 ↔ 自定义）、清除自定义排序（含二次确认）
- 节点下快捷新建子页面（含重名拦截与自动回滚）
- 在右侧栏打开节点对应页面
- 面板拖动、缩放、收回悬浮球、位置吸附
- 自动刷新、手动刷新、暂停自动刷新
- graph 级状态持久化
- 主题跟随与兼容性归一化

## 3. 总体架构

### 3.1 模块分层

#### 启动装配层

- `src/main.ts`
- 职责：注册设置、初始化插件实例、接线 DOM 事件、注册工具栏入口、处理插件生命周期

#### 业务协调层

- `src/plugin.ts`
- 职责：维护运行期状态、调度刷新、处理用户动作、协调树服务、布局服务与渲染层

#### 数据解析与索引层

- `src/tree-service.ts`
- 职责：读取收藏根、通过 Datascript 批量拉取页面与标签关系、构建 `parent -> children` 内存索引、提供路径查找能力

#### 事件过滤与检测层

- `src/db-change.ts`
- 职责：监听并深度过滤 `logseq.DB.onChanged` 事务事件，剥离块内容输入、换行分块、缩进移动等编辑噪音；精准识别页面标签属性（`:block/tags`、`tags::`、`parent::` 等）及页面生命周期变更；驱动实时精准刷新

#### 布局状态层

- `src/floating-layout.ts`
- 职责：管理面板与悬浮球的位置、尺寸、边界约束、吸附与拖拽缩放

#### 渲染层

- `src/render.ts`
- 职责：根据状态快照生成纯 HTML，保持 UI 与业务逻辑分离

#### 事件分发层

- `src/wire-dom-events.ts`
- 职责：从 DOM 事件中解析出具体交互语义，并转交给 `plugin.ts`

#### 设置与持久化层

- `src/settings.ts`
- 职责：读取用户设置、维护 graph 级内部状态、向 `logseq.updateSettings` 写回数据

#### 基础支撑层

- `src/constants.ts` / `src/types.ts` / `src/utils.ts` / `src/theme.ts` / `src/toolbar.ts`
- 职责：常量、类型、通用工具、主题同步与工具栏入口注册

### 3.2 模块依赖方向

- `main` 依赖 `plugin`、`wire-dom-events`、`toolbar`
- `plugin` 依赖 `settings`、`tree-service`、`db-change`、`floating-layout`、`render`
- `render` 只消费状态快照，不直接依赖 Logseq API
- `tree-service` 聚焦数据读取与关系解析，不承担 UI 状态管理
- `db-change` 聚焦 DB 事件事务过滤与标签变更判定，保持纯函数式检测
- `settings` 聚焦配置与持久化，不承担业务编排

该依赖方向保证了渲染层和数据层相对纯净，便于后续继续扩展功能而不让 `plugin.ts` 之外的模块承担过多协调逻辑。

## 4. 核心数据模型

### 4.1 配置项

当前公开设置项包括：

- `hierarchyProperty`：层级属性名，默认 `parent`
- `panelWidth`：悬浮面板默认宽度
- `pollIntervalSeconds`：自动刷新轮询间隔
- `sidebarPosition`：首次显示时默认靠左或靠右

### 4.2 运行期状态

运行期核心状态主要由 `plugin.ts` 维护，包括：

- 根节点列表
- 当前页标题
- 当前页路径
- 已展开节点集合
- 已加载节点集合
- 加载状态与错误状态
- 搜索关键字
- 最近定位节点
- 定位闪烁节点
- 自动刷新开关
- 功能区收起状态
- 排序映射
- 面板 / 悬浮球布局状态

### 4.3 graph 级持久化状态

graph 维度持久化数据包括：

- 展开状态
- 滚动位置
- 最近定位节点
- 视图模式
- 功能区收起状态
- 排序映射
- 面板位置与悬浮球位置
- 面板尺寸

其中图谱级状态通过 `__graphStates` 统一序列化保存，以避免不同 graph 相互覆盖。

## 5. 关键流程设计

### 5.1 启动流程

1. `main.ts` 注册设置 schema
2. 初始化插件实例
3. 绑定 DOM 事件
4. 注册工具栏按钮
5. 读取当前 graph 标识
6. 从设置中恢复 graph 级状态
7. 读取收藏页并生成根节点
8. 根据恢复状态渲染面板或悬浮球

### 5.2 树加载与索引构建流程

1. 启动时先加载收藏根节点。
2. 根节点按标题排序。
3. 用户首次展开某节点或触发全树加载时，确保子节点索引存在。
4. **两级索引构建流水线**：
   - **首选快速路径（Datascript 批量拉取）**：执行 `[:find (pull ?p [* {:block/tags [:db/id :block/name :block/original-name :block/title]}]) :where [?p :block/name _]]` 单次查询全图页面及其关联的标签实体，在内存解析并构建 `parent -> children[]` 映射与 `idToTitleMap` 页面 ID 反查字典。耗时由原先逐页串行 RPC 的 10~30 秒骤降至约 20ms（500+ 倍提速）。
   - **兜底并发路径（Chunked Fallback）**：若宿主 Logseq 环境的 Datascript 查询失败或不受支持，自动平滑降级至 `getAllPages()` 并按 `BATCH_SIZE = 25` 进行分块并发拉取页面属性，避免因单页异常或串行通信阻塞整树。
5. **双缓冲原子替换**：索引计算全程在内存后台完成，构建完成后原子置换 `childIndex` 与 `idToTitleMap`，更新过程中保留旧树视图，避免白屏闪烁。
6. 子节点按标题排序后返回；若当前层存在自定义排序，则在默认排序基础上应用覆盖。

### 5.3 当前页定位流程

1. 获取当前页面
2. 调用路径查找能力寻找所有命中路径
3. 将所有命中路径上的祖先节点标记为已展开
4. 记录当前定位节点
5. 触发渲染并滚动到目标节点
6. 若用户切换到其他页面，则自动清理旧定位标记

### 5.4 搜索流程

1. 输入搜索关键字
2. 进入搜索模式
3. 只保留命中节点及其祖先路径
4. 暂停拖拽排序入口
5. 渲染精简后的可见树
6. 清空关键字后恢复正常树浏览

### 5.5 排序流程

1. 默认按页面标题排序
2. 用户通过拖拽把手在同级内调整顺序
3. 将新顺序写入 `sortOrders`
4. graph 级持久化排序映射
5. 下次刷新时先走默认标题排序，再应用自定义顺序覆盖

### 5.6 布局交互流程

1. 面板支持拖动和右下角缩放
2. 标题栏双击可收回为悬浮球
3. 悬浮球点击恢复面板
4. 悬浮球拖动后自动吸附左右边缘
5. 所有布局结果按 graph 维度持久化

## 6. 排序方案设计

### 6.1 设计原则

- 默认排序必须稳定且可预测
- 自定义排序不能破坏新节点的自然接入顺序
- 同级排序与跨层级结构变更应明确区分
- 排序状态必须可以独立保存到 graph 维度

### 6.2 当前方案

- 根节点与子节点先统一走标题排序
- 使用 `ROOT_SORT_KEY` 代表根层排序
- 使用父节点的规范化 key 代表某一层级的排序空间
- `SortOrderMap` 只保存用户显式拖拽过的层级顺序
- 应用排序时先按自定义顺序输出已记录项，再追加未记录新项
- `SortModeMap` 记录每个层级的当前排序模式（default / custom）
- 切换到默认排序时保留 SortOrderMap 数据，仅改变 SortModeMap 标记
- 清除自定义排序时同时删除 SortOrderMap 与 SortModeMap 中对应条目，需用户二次确认
- UI 根据 SortModeMap 与 SortOrderMap 组合显示当前层排序状态

### 6.3 方案收益

- 新增节点不会因为旧排序映射而消失
- 默认顺序和自定义顺序职责清晰
- 不需要修改底层 DB 数据
- 刷新后排序结果仍保持稳定

## 7. 搜索与定位方案

### 7.1 搜索策略

- 搜索基于页面标题匹配
- 搜索结果保留祖先路径，避免命中项脱离上下文
- 搜索模式与排序模式隔离，防止用户在筛选态误改真实顺序
- 搜索多命中支持上一条/下一条切换导航，通过 `searchMatchKeys` 收集可见命中列表，`activeSearchMatchKey` 追踪当前位置

### 7.2 定位策略

- 当前页定位使用全路径查找，而不是首条路径命中即停止
- 多命中路径全部展开，保证用户看到完整上下文
- 定位标签跟随当前页变化自动失效，避免误导
- 聚焦当前路径模式：清空已展开集合后仅展开当前页路径
- 折叠其他分支模式：在保持当前路径展开的同时收起其他所有分支

## 8. 刷新与一致性策略

### 8.1 刷新来源与精准事件过滤

- **事件驱动精准刷新（`logseq.DB.onChanged`）**：
  - **核心痛点**：在 Logseq 中正常编辑文字、敲击回车换行分块（`split-block`）、Tab 缩进与移动块（`move-blocks`）都会产生底层 DB 事务，若不加节制刷新会导致目录树高频重载并打断写作流。
  - **精准过滤机制（`src/db-change.ts`）**：
    - **编辑噪音拦截**：对事务 Datoms（`txData`）、操作元信息（`txMeta`）及变更块（`blocks`）进行多维特征比对。凡仅包含 `:block/content`、`:block/title`、块结构链接（`:block/left`、大纲父块关系 `:block/parent`、`:block/order`、`:block/uuid`）以及系统时间戳（`:logseq.property/updated-at`）的常规笔记输入和排版操作，一律拦截忽略。
    - **有效属性变更识别**：当且仅当发生以下实质变更时判定刷新：
      - 标签实体与属性关联变动（`:block/tags`、`:block/properties`、`:user.property/*`）；
      - 配置的层级属性（如 `parent`）或通用标签键（`tags`、`page tags`、`page-tags`）变更；
      - 块文本中包含显式属性声明语法（如输入了 `tags:: [[xxx]]` 或 `parent:: [[xxx]]`）；
      - 页面级属性对象变更（自动排除系统固有块字段）；
      - 页面生命周期与收藏变更（创建页面、删除页面、页面重命名 `:block/name`、收藏夹变动）。
  - **防抖合并与队列补偿**：
    - DB 变化触发后经 200ms 防抖执行刷新，避免密集属性改动产生多次重复建树；
    - 引入待刷新队列标记（`pendingRefreshReason`）：若新事件到来时已有刷新任务正在执行，该事件不会被丢弃，而是在当前轮次完成后自动追发下一轮刷新，确保并发情况下数据 100% 最终一致。
- **轮询定时器（兜底）**：保留低频定时器兜底（默认关闭，可开启），用户可在设置中配置间隔或手动暂停。
- **用户手动刷新**：支持在界面工具区点击刷新按钮强制重建全树索引。

### 8.2 一致性与无感置换原则

- **双缓冲置换**：数据刷新期间旧树保持展示，新索引在内存后台构建完毕后原子替换，消除加载白屏与闪烁。
- **展开状态无损保留**：刷新后平滑保留用户已展开的分支节点和滚动位置。
- **非阻塞异步机制**：移除事件监听链路中的同步阻塞型页面属性读取，全链路保持纯异步，保障编辑打字丝滑无感知。
- **UI 状态与数据解耦**：数据解析层局部异常不影响 UI 框架稳定性。

### 8.3 自动刷新控制

- 用户可在面板内暂停自动刷新
- 暂停状态会持久化
- 轮询间隔由设置项控制

## 9. 持久化方案

### 9.1 存储方式

- 使用 `logseq.updateSettings(...)`
- 公开设置项与内部状态分离
- 内部状态不暴露在设置面板 schema 中

### 9.2 持久化粒度

- 全局粒度：面板可见性、自动刷新暂停
- graph 粒度：布局、展开状态、排序、功能区收起、最近定位节点、滚动位置

### 9.3 兼容性处理

- 支持从旧版分散字段迁移到新的 graph 级状态结构
- 对非法或缺失字段进行默认值回填
- 对排序映射与面板尺寸做归一化修正

## 10. UI 与交互设计原则

- 面板交互要轻量，不遮挡主要写作流
- 常用动作放在顶部工具区
- 标题栏承担拖拽与收回入口，但对 `i` 提示图标等交互做隔离
- 树节点信息层次清晰，状态尽量通过轻量样式表达
- 搜索、定位、排序三类能力互不打架

## 11. 风险与约束

### 11.1 数据约束

- 层级关系完全依赖页面属性质量
- 收藏夹本身的返回结构可能随 Logseq 版本存在差异

### 11.2 交互约束

- 当前拖拽排序仅在同级内生效
- 当前没有从插件内直接维护收藏夹的能力

### 11.3 性能关注点与优化现状

- **全量扫描开销（已解决）**：旧版逐页串行发起 `getBlockProperty` / `getBlockProperties`，千页图谱需 800+ 次 IPC，耗时高达 10~30 秒。现已重构为 Datascript 批量拉取（`buildChildIndexViaDatascript`），单次查询直接拉取全图页面及其关联的标签实体，索引构建降至约 20ms（500+ 倍提速）。
- **高频打字卡顿（已解决）**：通过 `src/db-change.ts` 深度过滤层，精准屏蔽普通文本输入、回车换行分块（`split-block`）和缩进，消除 99% 无关 DB 事务引起的无效树刷新。
- **并发与状态闪烁（已解决）**：通过双缓冲内存索引置换与待执行队列补偿（`pendingRefreshReason`），确保刷新过程无白屏无闪烁且不丢事件。
- **深层路径定位时的批量展开**：多命中路径展开开销受控于内存索引的高效反查字典（`idToTitleMap`）。
- **收藏根数量较多时的首屏渲染**：首屏节点渲染维持轻量 DOM 输出。

## 12. 后续演进建议

详细优先级、范围边界与排期建议见 [产品路线图 PRD](./product-roadmap-prd.md)。

优先级较高的后续迭代建议如下：

- 拖拽落点反馈增强
- 增加从当前页一键加入收藏 / 从树内移出收藏
- 针对大树场景补强性能与状态恢复兜底
- 搜索结果路径高亮
